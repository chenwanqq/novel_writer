# 基于世界写作

每部作品固定 `world_revision`，有独立修订链。创作简报保存观察者、时期、地点、核心问题、形式、文风及创作自由度。`Artifact` 保存人物、剧情弧、人物弧、伏笔、场景、风格和范例；作品接口无权改公共世界。

场景的 `reading_order` 为作品内唯一数字，`world_time` 是可选的作者数值时间轴。`pov` 与 `location` 引用已有世界或作品对象；场景目标、压力、选择、前后变化可放在 `data`。这些属于计划，不等于已发生事实。

`save_prose` 保存不可变正文，不改变连续性。`adopt` 在单次事务中采纳指定稿件及连续性清单。每条连续性必须有正文中的精确证据摘录；程序验证摘录存在，模型仍需区分人物说法、误解、梦境与真正发生的事。

连续性类别包括事件、人物知识、读者知识、信念、伏笔、兑现和关系。人物知识与信念需要 holder。读者知识按阅读顺序检索；人物知识按世界时间与当前 POV 检索，未知时间不擅自排序。修订已采纳场景会保守标记受影响记录 needs_review，排除出后续已确认上下文，等待对账重采纳。

`compile_context` 汇集世界约束、空间对象、作品材料、可用连续性和风格范例；它使用字符预算而非声称精确 token 数。范例只指导表达，不提供世界事实。`record_edit` 保存前后稿及修改理由，不自动采纳修订。

`impact` 报告显式依赖影响，不能穷尽自然语言因果；升级世界版本需要作者决策，正文不改写，连续性标记待审阅。多个作品可以继承不同世界版本。

## 演示文本审阅

合成作品《东港账簿》的已采纳片段：

> “库房的钥匙呢？”沈衡问。
> 陈大人摸了摸袖口。
> 沈衡把手伸了出来。

“摸袖口”给出迟疑的动作，“伸手”让沈衡继续施压；读者可以推测两人之间有阻力。正文尚未证明陈大人拒绝、藏匿钥匙或参与舞弊，所以演示只采纳“沈衡索取钥匙”这一有直接证据的事件。

另存的编辑范例把末尾改为“沈衡把手伸了出来。／‘交给小赵。’”，用于研究通过转移经办人表现阻力。单独看这个片段，发话人仍可能不清楚；放入完整场景时应交代说话动作或指向，不能机械照搬。该修改仅为风格范例，没有替换已采纳正文，也没有把“小赵”或权限转移变成世界事实。

这项审阅验证了正文证据与编辑范例的边界；文学效果仍需在具体长场景和作者反馈中继续检验。
