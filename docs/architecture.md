# 架构与运行边界

`models` 定义公共世界记录，`repository` 负责版本、事务、变更集和资源，`ingestion` 负责原文与提取进度，`atlas` 负责空间验证、行程和草稿，`works` 负责作品版本与连续性，`server` 和 `http` 仅为适配层。

SQLite 是结构化状态的唯一正式来源。世界与作品分别维护不可变修订链，分支头和作品头只在事务成功后前移。资源使用 SHA-256 内容地址；图片和正文更新产生新资源，旧版本仍可读取。每个短事务之后关闭连接。

世界与作品接口分开：世界记录不能通过 work_save 写入，正文不能直接作为世界快照提交。作者决策是审计记录，不是独立身份验证；本地单用户宿主权限仍控制谁能调用工具。

地图编辑器与 MCP 共用领域校验。HTTP 只监听回环地址，要求正确 Host、同源 Origin 及 Bearer token；运行时 token 不进入 Git 或备份。浏览器端用户文本在拼接 SVG/HTML 时转义，图片只允许受检验的位图，不加载外部 URL。

备份使用 SQLite online backup 生成一致数据库快照，并包含不可变资源与校验清单。恢复仅允许空目标，校验文件路径、内容哈希和数据库完整性后才发布结果。导出 Markdown 是只读视图。

首版采用完整修订快照与内存 Unicode 检索，适合个人世界资料库。字符预算不是精确 token 计量；语义一致性、时代合理性和文学效果仍需模型与作者审阅。不会声称检测到所有隐含依赖。

MCP 固定在官方 Python SDK 1.x 的兼容 API（依赖上限 `<2`），锁文件记录本次验证版本。日后升级 2.x 时应迁移服务器与客户端测试，而不是无上限升级破坏接口。
