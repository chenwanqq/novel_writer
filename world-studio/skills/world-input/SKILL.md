# 世界输入

世界是长期积累的主体。先用 `world_list` 定位世界与分支，再用 `world_read`／`world_search` 读取相关状态；不要靠聊天记忆重建。工具名称可能带宿主添加的插件前缀。

- 一次性导入：读 [资料导入](references/import.md)。归档和采用是两个动作，按单元读取全部分页并跟踪进度。
- 讨论与设定修改：读 [采用与冲突](references/canon.md)。明确采用可直接提交，探索性语言保留候选；不反复请求已经获得的授权。
- 地图与行程：读 [地图](references/atlas.md)。对话和地图页面引用同一套实体，通行耗时与画面距离分开。

## 持久化边界

变更顺序为读取基础版本 → `world_propose` → `world_preview` → 解决问题 → 在作者明确采用后 `world_commit`。每次逻辑请求使用稳定 key；重试沿用 key，内容变化必须换 key。版本过期时比较差异，不强行覆盖。

保存人物、制度、事件、事实、推演、未决问题的结构化定位与复杂说明。不要把所有信息拆成三元组；也不要只存一个无法追溯的大总结。`kind`、`nature` 和 `status` 分开，来源使用 `source_id/locator`。

工具返回成功才报告“已保存／已提交”，给出版本。无法访问的旧对话或附件明确列出；本 Skill 不是后台监听器，不保证自动捕获其他任务。

输入功能可长期独立使用，不追问主人公或高潮。用户同时要求更新世界和写作时，先完成世界提交拿到修订，再切换 `world-write`；不能让剧情需要绕过设定流程。
